# Tripzo — Flutter Mobile App

"Plan the trail. Book the stay." A Flutter (Android Studio–ready) mobile client for the
existing Tripzo Node.js/Express + MySQL backend. This app **does not** include a backend —
it only consumes the REST API your `tripzo-backend` already exposes.

## What's included

- `lib/core` — theme/design tokens matching the web app, and the Dio API client with a
  JWT auth interceptor + secure token storage (`flutter_secure_storage`, wrapped in
  try/catch so corrupted storage can't crash the app).
- `lib/models` — Hostel, Room, Booking, Negotiation, Review, Notification, User.
- `lib/services` — one file per backend domain, covering every endpoint in the spec:
  auth, hostels, bookings, negotiations, reviews, waiting list, notifications, trips,
  packages, weather, budget, chatbot, chat, admin.
- `lib/providers/auth_provider.dart` — session state (login/logout/restore).
- `lib/widgets/state_widgets.dart` — shared loading/error/empty states, password
  show/hide field, and a confirm-before-destructive-action dialog.
- `lib/screens/` — full auth flow (login, traveler signup, owner 3-step signup with
  camera/gallery CNIC upload, OTP verify), traveler tabs (Explore, Hostel Detail with
  negotiate/book, My Trips, Trip Planner, Chat — AI assistant + owner conversations,
  Profile), owner tabs (Dashboard with a bookings-by-property chart, My Hostels,
  Add/Edit Hostel, Room Management, Bookings, Offers/negotiation inbox, Profile), and a
  simplified single-screen Admin section (pending approvals, users, hostels, stats).

**Scope note:** every API endpoint from the spec has a typed service method, and every
screen listed in the spec exists and is wired to real data (loading/error/empty states
throughout, per the web app's UX notes). A few secondary actions are stubbed with
`onTap: () {}` placeholders you'll want to wire up next — trip group detail/memories,
opening an individual chat conversation thread, waiting-list/budget/weather sub-screens
from the traveler Profile menu, and the negotiation auto-accept/counter rules editor.
The service methods for all of these already exist in `lib/services/misc_services.dart`
— the remaining work is UI, not API integration.

## First-time setup (Android Studio)

This project ships `lib/`, `pubspec.yaml`, and `.env` only — not the generated
`android/` and `ios/` platform folders, since those must be generated by the Flutter
version you have installed.

1. Install Flutter (3.22+) and open Android Studio with the Flutter/Dart plugins.
2. Unzip this project somewhere, then in a terminal inside that folder run:
   ```bash
   flutter create .
   ```
   This generates `android/`, `ios/`, and other platform folders **without**
   overwriting your existing `lib/` or `pubspec.yaml`.
3. Install packages:
   ```bash
   flutter pub get
   ```
4. Edit `.env` and point it at your running backend:
   ```
   API_BASE_URL=http://10.0.2.2:5000/api
   UPLOADS_BASE_URL=http://10.0.2.2:5000/uploads
   ```
   - `10.0.2.2` is the special alias the **Android emulator** uses for your computer's
     `localhost` — use it if the backend runs on the same machine as Android Studio.
   - On a **physical device**, use your computer's LAN IP instead (e.g.
     `192.168.1.5`), and make sure the phone is on the same Wi-Fi network and your
     backend's `PORT` (5000) isn't blocked by a firewall.
5. Open the folder in Android Studio (`File → Open`), let it index, pick an emulator or
   plugged-in device from the device dropdown, and hit **Run** (▶). Or from the
   terminal:
   ```bash
   npx expo start   # ← not this, that's the old RN prompt
   flutter run
   ```

## Backend

Start your existing backend first (from `tripzo-backend/`):
```bash
npm install
npm start
```
Confirm it's listening on port 5000 before launching the app, or every screen will show
its "couldn't reach the server" error state.

## Design tokens

Colors, radii, and type scale live in `lib/core/theme.dart` and mirror the web app:
primary `#1A56DB` → `#2563EB` gradient, secondary `#0EA5E9`, gray-50…900, Inter font
via `google_fonts`, 12–16px card radii, pill-shaped status badges.
